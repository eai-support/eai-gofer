# Operating Model

Design how the organization must work to deliver the strategy.

## Input

- The strategy, current organization data, and design constraints.

## Method

1. Write 5 to 7 design principles that come from the strategy.
2. Describe the current state and the target state for each element:
   - Structure: organization type (functional, divisional, matrix), spans, and layers.
   - Processes: the key end-to-end processes. Map one process in detail with `process-mapping`.
   - People: roles, capabilities, and sizing.
   - Governance: run-state forums, decision rights, and cadence.
   - Technology and data: core systems and data ownership.
   - Locations and sourcing: in-house, shared services, or outsourced.
   - Performance management: how results are measured.
3. For structure choices, compare 2 to 3 options against the design principles.
4. List the gaps between current and target.

## Output

1. Operating model table: Element | Current | Target | Gap.
2. Structure options with trade-offs and the recommended option.

## Quality bar

- Every target choice traces to a design principle.
- Decision rights are stated at the forum level.

## Boundaries

- Not for role-level responsibilities: use `raci-builder`.
- Not for the transition plan or programme governance: use `implementation-roadmap`.
- Not for the people transition: use `change-plan`.
- Not for how AI changes roles and skills: use `ai-workforce-plan`.

## Rules

- If a required input is missing, ask once when you can. Otherwise state an assumption, label it [Assumption], and continue.
- Do not invent facts, figures, or sources. Use provided material or sources you can check; label other knowledge [Unverified] and estimates [Estimate].
