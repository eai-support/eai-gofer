# Problem Framing

Convert a loose request into a problem statement that a team can solve and a decision maker can accept.

## Input

- The request, plus any context on the business, the trigger, and the deadline.

## Method

1. State the decision this work will inform and who makes it.
2. Write the key question: specific, measurable, action-oriented, time-bound. Example: "How can we raise EBIT margin from 8% to 12% by FY27 without cutting R&D?"
3. Describe the context and the trigger: why now.
4. Set scope: what is in, what is out.
5. Define success criteria as measurable outcomes.
6. List constraints: budget, time, policy, things that must not change.
7. Name stakeholders and sources of insight.
8. Test the question: would a clear answer change a decision? If not, reframe.

## Output

A problem statement worksheet with these fields: Decision and decision maker, Key question, Context, In scope, Out of scope, Success criteria, Constraints, Stakeholders, Deadline, Open questions.

## Quality bar

- One key question, not a list of topics.
- Success criteria can be measured.
- Scope exclusions are explicit.

## Boundaries

- Not for profiling who will receive the answer: use `audience-brief`.
- Not for splitting the question into parts: use `issue-tree`.
- Not for the engagement scope, team, timeline, and fees: use `engagement-proposal`.
- Hand off to: `issue-tree`, `audience-brief`.

## Rules

- If a required input is missing, ask once when you can. Otherwise state an assumption, label it [Assumption], and continue.
- Do not invent facts, figures, or sources. Use provided material or sources you can check; label other knowledge [Unverified] and estimates [Estimate].
